# محور هفتم: دسترسی خصوصی، رابط واکنش‌گرا و پایداری Polling

مبنای این تغییرات، Commit 31c91c59ed221fcd6546d96506967d425c9df4ee است.

## دسترسی به داده‌های خصوصی

API مربوط به Job، تاریخچه، مقایسه، Prompt ذخیره‌شده، Upload، خروجی، Workflow کامل و وضعیت زیرساخت اکنون به APP_INTERNAL_TOKEN نیاز دارد. همان توکنی استفاده می‌شود که رابط فعلی برای عملیات مدیریتی به کار می‌برد؛ سیستم حساب کاربری جدیدی اضافه نشده است.

اگر APP_INTERNAL_TOKEN در فایل خصوصی .env سرور خالی باشد، این APIها با HTTP 503 بسته می‌مانند. رابط کاربری دلیل را نشان می‌دهد، بارگذاری مرجع و Generate را غیرفعال می‌کند و وضعیت قطع‌شدن شبکه را به‌اشتباه گزارش نمی‌کند. توکن در حافظه همان تب مرورگر می‌ماند و بعد از Refresh باید دوباره اعمال شود.

/health و فهرست خلاصه ابزارها برای شروع رابط باقی می‌مانند. APIهای Worker همچنان توکن مستقل Worker را می‌خواهند. لینک دانلود امضاشده همچنان کوتاه‌مدت است و فقط پس از بررسی دسترسی و تعلق Asset به Job صادر می‌شود.

این نسخه مدل کاربری تک‌اپراتوری دارد: توکن یکسان به کل داده‌های همان Controller دسترسی می‌دهد و جداسازی چند کاربر یا چند Tenant را فراهم نمی‌کند.

## رابط و Polling

- Polling وضعیت Instance در تب پنهان متوقف می‌شود؛ خطاهای متوالی با فاصله افزایشی تا ۶۰ ثانیه دوباره امتحان می‌شوند.
- وضعیت مرورگر از وضعیت Worker تفکیک می‌ماند و پاسخ‌های HTTP از API به‌عنوان قطع شبکه تفسیر نمی‌شوند.
- فوکوس صفحه‌کلید واضح‌تر است، هدف لمسی کنترل‌ها در موبایل بزرگ‌تر شده و تنظیم prefers-reduced-motion رعایت می‌شود.
- Prompt و مقادیر فنی در متن مختلط از جهت مناسب استفاده می‌کنند.
- منطقه زنده Job فقط نام مرحله/وضعیت را اعلام می‌کند؛ درصد متغیر هر Poll به‌صورت اعلان پیوسته خوانده نمی‌شود.

## تغییرات داده و استقرار

Migration پایگاه داده لازم نیست. پیش از Build، مقدار طولانی و تصادفی APP_INTERNAL_TOKEN را در فایل خصوصی .env سرور تنظیم یا مقدار موجود را حفظ کنید. توکن واقعی را در GitHub یا بسته Patch قرار ندهید.

آزمون‌های مرورگر و یکپارچگی با GPU/Salad در این محیط اجرا نمی‌شوند. محدودیت و نتیجه هر بررسی در گزارش محور هفتم آمده است.
