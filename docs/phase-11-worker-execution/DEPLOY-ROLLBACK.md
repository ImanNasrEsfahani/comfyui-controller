# Deploy and rollback — isolated STAGING plan ONLY

1. Obtain an independent disposable checkout of the **exact SHA** `41b11228bc4728b2781966eafb6d23fe1831cb2f`. Do not use a later `main` without rebuilding the patch. Check that the repository has all Phase01–10 migrations, source-pinned scripts, and modules. `GLOBAL-RULES.txt`, signed `DECISIONS.md` and approved runtime/model pairs are blockers.
2. Put Phase11 ZIP files in the same relative paths. The ZIP contains only additions + the installer, not full replacements of `main.py`, `job_records.py`, `pull_worker.py` or `Dockerfile`. Review every diff and make an external, tested database backup before ever deploying.
3. On the checkout, run `python scripts/phase11_prepare_checkout.py --repo .` (dry-run, no edits). Once all anchors and source SHAs are reviewed on this disposable checkout, you may use `--apply` **there only**; it writes four `.phase11.bak` sibling backups. It composes previous router imports and guarded v11 Worker/Docker changes. Re-running after patch is deliberately refused.
4. Test schema only with `python scripts/phase11_migrate_copy.py --source /path/to/TEST.db --destination /path/to/new-stage11-copy.db --repo .`. The source is read-only and backed up with SQLite's online Backup API, not a filesystem copy. The target must not exist. Run `PRAGMA integrity_check`/`foreign_key_check` and phase11 tests on the copy.
5. **Keep both flags OFF**: `WORKER_V11_CAPABILITIES_ENABLED=false`, `WORKER_V11_EXECUTION_ENABLED=false`. Existing worker and Salad profile/image stay untouched. Only if Phase03 owner-safe acceptance, Stage07 digest/registry approval, Stage09/10 real compiled graph, trusted signing key distribution, OCIs scan and GPU staging approvals are independently verified should you design a separate controlled activation window. Enabling the Worker flag while old unsigned queue requests exist will reject those jobs.
6. Never introduce Docker image `:latest`, mutate running image digest, download unverified model paths, drop old queue tables, rewrite R2 keys or overwrite existing production `.env`. No arbitrary model URL or user Docker image path is accepted.
7. Rollback on isolated checkout: stop any test containers, disable both flags, restore four `.phase11.bak` copies as reviewed; keep all recorded DB backups. Do **not** delete additive migration/old jobs or object keys as a rollback shortcut. Do not attempt real Salad rollbacks without provider state checks and a drain plan.

**Untested installer limitation:** This tool cannot clone GitHub directly in the current Python container. Its exact original blob guards were compared against GitHub read-only metadata, and synthetic source-anchor tests pass, but a full checkout dry-run plus `git diff`, CI and staging regression are still required.
